# draft-or-done

AIアシスタントが下書きやカートなどの中間状態を「完了」と言ってしまうのを防ぐ、Claude向けスキル。完了は、言い方ではなく証拠で決める。

## 何をするスキルか

AIに買い物、送信、予約、投稿、公開を任せると、ときどき起きるのが「やったはずが、やれていない」だ。逆もある。「失敗した」と報告されたものが、実はできていた。どちらも原因は同じで、**中間状態と完了状態の取り違え**。

- カートに入れただけで「購入しました」
- 下書きが保存されただけで「送信しました」
- ビルドが成功し、デプロイがReadyになっただけで「本番に反映しました」
- アップロードが97%まで進んだだけで「保存しました」

このスキルは、その取り違えを型で潰す。中身は大きく3つ。

1. **状態の階段**：買い物・送信・予約・投稿・保存・デプロイ・申込の7分野について、状態を階段として並べ、今いる段を名指してから報告する
2. **証拠の型カタログ**：分野ごとに「完了の証拠になるもの／ならないもの」を表で決め、証拠の強さ（強い／中くらい／弱い）で扱いを分ける。強い証拠が1つ示せない完了は言わない
3. **報告の型**：報告は「状態＋証拠＋残り」の3点セットにする。報告が食い違ったら新しい方を採用せず、証拠に戻って訂正する手順まで決めてある

著者の運用で実際に起きた取り違えが、このスキルの元になっている。送信に失敗したと報告されたメッセージが実は送信済みだった件。リポジトリにファイルがありデプロイもReadyだったのに、配信元の取り違えで本番に反映されていなかった件。アップロードが97%で止まったバックアップの保存状態が未確認だった件。いずれも「画面は正しく見えていた」のに、完了ではなかった（あるいは、完了だったのに失敗と報告された）。

対象は、日々の業務の取引状態。コードのテストやビルドの検証そのものを扱うスキル（同名の考え方で作られたものがGitHub上にいくつかある）とは、対象が違う。あちらは「コードが本当に動くか」、こちらは「買い物・送信・予約・公開が本当に確定したか」。

## 使い方

Claude CodeやClaudeのスキル対応環境で、`skills/draft-or-done/SKILL.md`を読み込める場所に置く。テンプレート（`skills/draft-or-done/templates/`）と証拠定義の見本（`proofs.example.md`）はSKILL.mdから参照されるので、フォルダごと置く。

### Claudeのチャット（claude.ai・デスクトップアプリ）で使う

設定の「機能」で「クラウドでコードを実行」と「外部ネットワークへの通信を許可」をオンにしてから、新しいチャットで次のように送る。

```
https://github.com/ai-jissen-lab/draft-or-done のスキルを使えるようにして
```

うまくいかないときは、`skills/draft-or-done`フォルダを丸ごとzipにして、「設定」の「Skills」からアップロードする。

### Claude Codeで使う

```
git clone https://github.com/ai-jissen-lab/draft-or-done.git
cp -r draft-or-done/skills/draft-or-done ~/.claude/skills/
```

置いたあとは、買い物や送信、予約や公開を任せるときに自動で効く。「本当に買えた？証拠を見せて」のように頼めば、明示的にも使える。

## 最初に使うとき

組み込みの証拠カタログだけでも動く。ただし、同じサービスを繰り返し使うなら、そのサービスの「完了の証拠」を`proofs.md`に定義しておくと判定が安定する。`proofs.example.md`を`proofs.md`という名前でコピーし、実際の確定画面や履歴を見て書き換える。定義は思い込みで書かず、実物を見てから残すのがこのスキルの流儀。
